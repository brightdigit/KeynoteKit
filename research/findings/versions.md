## App-identity anomaly (investigated, accepted as genuine Keynote)

The installed app presents as `Keynote Creator Studio.app` with bundle id
`com.apple.Keynote` (older Keynote used `com.apple.iWork.Keynote`) and a
non-Apple `TeamIdentifier=JCRTNEU7GK`. Forensic checks that resolved it in
favor of genuine Keynote:

- Mac App Store distributed: has `Contents/_MASReceipt/receipt`; Gatekeeper
  `spctl` returns `accepted`, `source=Mac App Store`, Apple signing chain
  (`Apple Mac OS Application Signing` -> `Apple WWDR CA` -> `Apple Root CA`).
- Links the real iWork private frameworks (`@rpath/Keynote.framework`,
  `@rpath/TSUtility.framework`) under hardened runtime with **library
  validation** enabled, so those frameworks are signed by the same team as the
  app (i.e. this is a real Keynote code build, not stitched-in binaries).
- Ships the authentic `Keynote.sdef` and the genuine
  `com.apple.iwork.keynote.*` document/UTI types.
- `CFBundleName=Keynote`, so `tell application "Keynote"` resolves to it.
- **Empirical clincher:** files it saves unpack into authentic iWork IWA
  (`KN.SlideArchive`, `TSP.ArchiveInfo`, ...). See round-trip below.

Conclusion: treat as genuine Apple Keynote 15.3. The unusual name/bundle id is
cosmetic/registration only.

## Round-trip validation (unpack -> pack -> reopen)

Test deck: one blank slide + one text item ("RoundTrip"), scripted via
osascript, saved to `samples/roundtrip.key` (465 KB).

| Step | Result |
|---|---|
| `keynote-parser unpack` | **PASS** — 55 files, authentic `Index/*.iwa.yaml`, `Data/`, `Metadata/`, previews. Text survives; slide carries a `transition:` block. |
| Reopen ORIGINAL `.key` in Keynote | **PASS** — opens, 1 slide (AppleScript control). |
| `keynote-parser pack` | Runs; emits `samples/roundtrip_repacked.key` (463 KB). |
| Reopen REPACKED `.key` in Keynote | **FAIL** — Keynote opens no document (silently rejects it). |

### Interpretation

This is the anticipated **version gap**: keynote-parser 1.14.4.0 maps Keynote
<= 14.4, but this Keynote is 15.3. Unpacking is tolerant (unmapped 15.3 fields
are preserved as raw under `unknownFieldRule: IgnoreAndPreserve`), so the YAML
dump is faithful and diffable. Re-packing, however, does not reproduce a
byte/structure layout Keynote 15.3 will accept.

### Impact and decision

- **Phase 1 (transitions) is unaffected.** The experiment pipeline
  (`run_experiment.py`) only does unpack -> normalize -> diff; it never packs.
  Differential diffing of authentic unpacked decks is fully valid. Proceeding.
- **Pack is required only for the future template-surgery backend**, not for
  reverse-engineering. Regenerating mappings is therefore deferred as a backend
  prerequisite, not a Phase 1 blocker.

### Mapping regeneration (follow-up, when pack is needed)

`keynote-parser/mapping.py` is generated by the upstream repo's
`dumper/generate_mapping.py` (header says so) and is **not** in the installed
wheel. Regenerating for 15.3 requires the keynote-parser source tree plus its
`proto-dump` step run against the installed `Keynote.framework` binary to
extract updated `.proto` definitions, then recompiling the `generated/*_pb2.py`
modules. Track as a separate task before relying on `pack`.
